# 测试精简决策案例

主流程遇到删除、兼容、安全、迁移或重复边界不明确时读取本页。

## 删除内部能力

内部 CSV 导出页面和服务永久退役，且没有剩余合同：删除专用格式化单测、内部导出 API 成功测试、按钮 UI 测试，以及专属 fixture、mock、snapshot、builder、无用权限、配置和文档。

本次变更一次性搜索旧标识，例如：

```bash
rg 'ExportService|/export|exportButton|EXPORT_FEATURE' .
```

随后运行构建、类型检查、路由注册检查和相关应用 smoke。匹配结果逐项核对消费者；只有“禁止重新引入”仍是明确产品或安全要求时，才长期保留缺失断言。

## 退役公共 API

`/v1/reports/export` 已退役，但受支持客户端仍可能调用一个发布周期：保留合同测试验证约定状态码、稳定错误结构和必要迁移链接，并记录支持窗口结束条件。成功导出已不再支持时，其成功路径测试删除；保留拒绝合同不要求保留旧实现。

## 删除涉及安全的入口

新授权路径上线后移除旧管理员入口：保留安全测试，确认未登录或非管理员请求无法通过旧路由或等价能力绕过权限。网关与应用保护不同边界时，在实际可能失效的边界做集成测试。除非源码规则本身就是安全控制，否则不要仅断言私有路由表或源码字符串。

## 删除字段但存在历史数据

模型移除 `legacy_status`，存储中仍有旧记录：保留读取、转换和序列化所需的迁移与旧数据兼容测试。只有迁移完成、支持窗口结束，且有证据确认旧数据和受支持客户端不再依赖该行为时，才删除这些测试。

## 不同层级的相似测试

订单金额单测保护折扣、税、舍入和边界组合；端到端金额断言保护完整可见流程、持久化和币种接线，二者可以同时保留。端到端只选少量代表性金额，详细组合放到单元或集成层。执行同一生产代码行不足以证明冗余。

## 内部交互断言

支付回调验证下游调用次数和顺序：若重复调用会二次扣款、顺序决定协议结果，或调用次数是幂等/并发保证，则保留交互断言。若只是照抄当前方法执行顺序，应通过公开返回结果或持久化副作用验证。

## 评审问题

- 每个保留或新增测试保护什么当前行为，什么实际错误会使它失败？
- 哪些测试和辅助资源只属于已删除能力，哪些仍有共享消费者？
- 每个缺失或拒绝断言是否有有效的产品、安全、兼容或迁移合同？
- 重复判断是否比较了输入、断言、边界和失败模式？
- 关键路径、权限、数据、幂等、外部合同、迁移和真实缺陷保护是否保留？
- 哪些检查只做本次验收，哪些属于长期回归？实际运行了什么，仍有什么未验证？
