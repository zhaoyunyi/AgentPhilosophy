# 公开历史清理与重新接入

2026-11-10，维护者授权删除历史中的内部项目名称、本机路径与跨项目证据链接。清理覆盖公开分支、标签、提交消息、文件名及内容；历史案例保留方法和测量数据，名称改为示例，原项目链接不再分发。

## 版本身份变化

这是经维护者明确授权的历史清理例外。所有受影响的提交 SHA 已改变，原有版本号保留；34 个 Release 的下载附件从改写后的标签重新构建，并更新 SHA-256 与已有发布回执。旧 CI 成绩证明的是改写前快照，不能用来证明新附件；本轮新主线测试与安装验证单独记录。

已经固定旧 SHA、缓存旧 wheel 或保存旧升级目标 JSON 的项目，应重新检查 Release 并获取当前固定提交，使用该提交重新安装 CLI。不要通过合并旧分支把原始历史带回仓库。

## 本地仓库处理

推荐先保存自己的未提交文件和必要补丁，再重新 clone。需要保留原 clone 时，只迁移自己的补丁到新主线，并检查补丁不包含已删除的项目身份；不要把旧 main 直接 merge 回来。其他独立工作区和他人 clone 不会被本次远端改写自动清理。

项目已有模块和 custom 保留。历史案例文件更名可能使升级预览列出输出退役；先核对 diff 和手改冲突，再由项目维护者决定是否采用该迁移。旧版安装包里的来源记录仍可能采用绝对路径；主线的便携来源修复在后续正式版本中分发。

## 仍需平台处理的范围

GitHub 管理的旧 PR 引用、缓存页面和不可达提交可能继续保留旧对象，普通强推不能删除它们。应依据本机保存的清理记录联系 GitHub 支持，处理旧 PR 引用和缓存。已下载副本、fork、他人 clone 和搜索引擎缓存不属于仓库维护者可以单方面清除的范围。

本机旧历史备份仅用于恢复，保存在仓库之外且限制文件权限；不得提交或重新上传。公开说明不列出原敏感名称或旧对象地址。
