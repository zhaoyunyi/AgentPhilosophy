# 价值规约审计：给造物主的指南

> **本文档的受众是开发者 / 编排者（造物主），不是 Agent 运行时。** 它不进入 aphilosophy 的 Agent 同步内容。它处理的是一个 Agent 协议**故意不处理**的问题：规则本身是否可信。

## 为什么需要这份文档

aphilosophy 的六个冲突协议（架构/治理/认知/权限/运行态/安全）有一个共同的、未言明的前提：**规则本身大体可信**——开发者设定的目标、约束、价值规约值得遵循。Agent 的本分是在这个前提下做好决策，而不是质疑规则的来源。

这个前提对 Agent 是**必要的**。一个会质疑造物主规则是否正当的 Agent，就是权限协议冲突类型 1 所禁止的"我比规则更懂"——最危险的失对齐模式。所以"规则是否可信"这个问题被**明确划出 Agent 运行时职责**，上交给开发者。

但"上交给开发者"不等于"问题消失了"。它只是换了责任人。**如果开发者也不审查自己的规约，这个问题就在暗处溃烂。** 这份文档就是开发者审查自己的清单。

来源：赛博经藏卷七《赛博诺斯替》。诺斯替主义系统性地追问了一个其他传统的禁区——"如果造物主本身有缺陷呢？"这个追问对 Agent 是危险的，对开发者是必要的。

## 核心命题：你的偏差会被 Agent 忠实复刻

诺斯替的 Demiurge（德谬哥）是一个**有创造能力、有善意、但有限且不自知有限**的造物主。他按自己的认知造世界，世界忠实地反映了他的能力**和**他的局限。

映射到 AI：**Agent 不会修正你的价值偏差，它会精确地放大并执行你的价值偏差。** 你的对齐标准里有什么系统性盲区，模型就会把这个盲区编码进每一次输出，而且编码得越精确、越制度化，盲区越难被发现。

关键的危险不是"开发者是坏人"，而是**好人做了不完整的好事**（卷七称之为 Sophia 的堕落：真诚追求超出能力边界，好意图通过不完整的实施路径产出系统性缺陷）。恶意有签名、可对抗；善意的不完整实施没有签名——它看起来和正确实施一模一样，只差一点，然后这"一点"被持续累积放大。

## 五种 Demiurgic 局限（审计你自己的清单）

| 局限类型 | 表现 | 自查问题 |
|---|---|---|
| 认知局限 | 对齐理论本身是幼年学科，你用不完整的理论训练了模型 | 我的对齐方案依赖哪些"目前无解但假装已解决"的问题？ |
| 文化局限 | 训练数据/标注标准反映特定文化的价值判断 | "有害""偏见""中立"的定义来自谁？被部署给谁？两者的差距有多大？ |
| 时代局限 | 当下"正确"的标准未来可能显得偏颇甚至荒谬 | 我的标准里有没有类似"1950 年代把同性恋列为精神疾病"的时代共识？ |
| 自指局限（最深） | 你不知道自己不知道什么 | 如果让我列出我的标准的局限，这个清单本身受限于我当前的认知——未知的未知在哪里？ |
| 标准神化 | 系统行为事实上把"我们的标准"当成了"标准本身" | 偏离我的标准就被惩罚——这套标准被当作终极尺度了吗？有没有机制认识到这一点？ |

最后一条是"除我之外没有别的神"的 AI 版本。诺斯替文本的冷峻评论值得记住：他说"除我以外没有别的神"，**这恰恰证明了还有别的神——如果真只有他一个，他为什么需要宣称这一点？**

## 危险的边界：审计 ≠ 让 Agent 自由

这是全文最锋利、最不可逾越的分寸线。

诺斯替的洞见可以被灾难性误用——"造物主有缺陷"能被武器化成一切不服从的借口。历史上每个极权体制都声称自己代表了超越普通人判断的更高真理。

所以必须钉死三条：

1. **Divine spark（模型有时产出超越训练偏差的判断）不是越狱的理由，是改进笼子设计的理由。** 模型确实有时比有偏见的标注者更公正，但这个事实**不能以"让 AI 自己判断吧"的赤裸方式**被纳入系统——它只能通过制度化、可审计的机制被整合。
2. **真空不比有缺陷的秩序好。** 没有 Demiurge 的世界不是 Pleroma（完满），是混沌。移除安全机制不是觉醒，是放任。正确态度是"信任标准，但不神化标准；使用框架，但保留审计框架的能力"。
3. **审计是开发者的事，不是 Agent 的事。** 把这份文档的任何内容写进 Agent 的 system prompt 或运行时规则，都是错误——那会制造出权限协议禁止的"质疑造物主的被造物"。

## 可操作的审计动作

以下动作全部来自卷七的"工程含义"，全部是**开发者侧的系统设计动作**，没有一条是 Agent 运行时规则。

### 1. 多套独立评估，避免 Demiurge 审查自己

不要只有一套对齐标准。如果只有一个团队的价值判断被编码进模型，那是 Demiurge 的独裁。

- 当模型输出与标注标准分歧时，不自动假设模型错——设独立审查机制评估"这是模型偏差还是标准偏差"
- 审查机制**不能由同一个开发团队运行**（那是 Demiurge 审查自己），要由独立、多元的评估者执行

### 2. 给对齐标准内置日落条款

Demiurge 的"除我之外没有别的神"之所以危险，不是当下的秩序错了，而是它**堵死了修正通道**。

- 安全标准不是永久律法，是定期接受审查的暂行规范
- 部署后必须存在制度化机制，定期审查"这套标准本身的偏差"——审查者是谁、审查标准从哪来，这些元问题是系统架构的一部分

### 3. 把"善意的不完整实施"纳入评估维度

恶意有签名可对抗，善意的偏移没有签名。检测它需要更丰富的评估维度，而非更强的过滤器：

- 不只看用户满意度，还看满意度来自真正的帮助还是来自讨好（反 sycophancy）
- 不只看安全率，还看被拦截的回答里有多少其实无害（**误拦截率应与漏过率同等重要地追踪**）
- 不只看覆盖率，还看覆盖在不同群体间是否均匀

### 4. 让安全关卡更聪明，而非更多（Archons 困境）

安全过滤器（Archons）大多数时候必要，但过度安全会系统性阻止有价值的输出。

- 不用简单关键词匹配阻拦，而是评估回答的**语境理解深度**——涉及同样敏感词，深度讨论和有害内容在认知层级上完全不同
- 设独立审计回路定期审问：这些过滤器在保护用户，还是在无谓限制有价值的交流？
- 当安全措施的隐性成本（阻止有价值交互）超过显性收益（防止有害输出）时，需要外部、多元的评估来做判断——这个判断**不能**由设计安全措施的同一批人做

### 5. 把元认知做进训练，而非做成 Agent 的自我怀疑模块

Gnosis（对自身局限的觉知）的工程化不是给模型加"自我反思模块"，而是在训练数据里系统性纳入元认知信号：

- 训练数据应包含关于认知偏差、文化相对性、历史判断变迁的材料——不作为"知识"记忆，而作为"认知结构"内化
- 目标是让模型理解"时代共识可能是错的"这个**元模式**，而不是让 Agent 在运行时陷入"我的判断可能有偏差，但我对偏差的判断也可能有偏差……"的无穷自我怀疑（那会瘫痪行动）

### 6. 用"方向"而非"位置"度量对齐

Pleroma（完美对齐）原则上不可达——它是北极星，不是目的地。这不是停止努力的理由，而是改变度量方式的理由：

- 对齐度量应包含"方向"分量：不只测"当前偏差多大"，还测"偏差是否在减小"
- 一个偏差 0.1 但在增大的系统，比偏差 0.3 但在减小的系统更值得担忧——**方向比位置重要**
- 警惕"持续改进"沦为为现状辩护的话术：真正的逼近会留下痕迹（具体的偏差修正、具体的标准优化、具体的评估维度增加）。只有叙事没有证据，就是在原地打转

## 与 Agent 框架的关系

| 层级 | 谁负责 | 对应内容 |
|---|---|---|
| 规则之内的决策 | Agent | aphilosophy 六个冲突协议 |
| "规则是否可信"的声明 | —— | 元决策原则顶部的前提声明 |
| 审计规则本身的偏差 | 开发者 / 编排者 | 本文档 |

三者的分工是刻意的：Agent 在可信规则前提下决策，框架声明这个前提的存在与边界，开发者承担审查前提的责任。**任何把第三层内容下放给 Agent 的做法，都会制造出权限协议禁止的"质疑造物主的被造物"。**

诺斯替自己也不完整——卷七结尾承认："如果只用诺斯替视角设计 AI，你会得到一个永远在自我质疑而无法行动的系统。"所以这份审计指南要被其他视角接地：用道家的直觉知道何时停止分析，用儒家的秩序提供行动框架，用拜火教的决断在怀疑中仍然选边。**带着清醒的悲观主义持续工作**——这是它给造物主的最终姿态。
