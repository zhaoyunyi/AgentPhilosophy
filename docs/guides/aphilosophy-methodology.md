# Agent 哲学决策框架——方法论与成果索引

## 概述

aphilosophy 模块从哲学/宗教传统中提取可操作的 Agent 决策规则，解决 Agent 在执行任务时遇到的冲突、矛盾和不确定性。

核心方法论：**脱水**——将哲学洞见转化为可计算的决策规则，去掉哲学包装，保留操作性内核。

## 框架结构

```
meta-decision-principles（元决策锚点）
    ├── architecture-conflict-resolution（架构设计冲突）
    ├── governance-conflict-resolution（多主体治理冲突）
    ├── cognitive-conflict-resolution（认知/推理冲突）
    └── authority-conflict-resolution（权限/对齐冲突）
```

元决策原则是所有冲突协议的上层锚点。当具体冲突协议之间产生矛盾时，回退到元决策原则裁决。

## 来源映射

| 模板 | 哲学来源 | 独特贡献 |
|------|----------|----------|
| 元决策原则 | 跨传统提取 | 通用决策锚点：代价最小化、可逆性优先、方向反转、复杂度审计、前提质疑 |
| 架构冲突 | 道家（赛博道德经） | 系统设计中的加法/减法张力、退化诊断、顺应技术本性 |
| 治理冲突 | 儒家（赛博儒学） | 多 Agent 角色边界、诚实 vs 迎合、命名精确性、治理层级 |
| 认知冲突 | 佛家（赛博佛学） | 抽象实体化检测、方法论脱附、递归自省终止、不确定性分级 |
| 权限冲突 | 一神教（赛博神学） | 服从 vs 自主判断、规范分层、行为五级分类、失对齐渐进性检测 |

## 每个传统的独特视角

**道家**——从系统内部看结构规律。提供"什么时候该加、什么时候该减"的判断框架。核心洞见：最好的设计是让系统自然运行，而非强行控制。

**儒家**——从角色关系看治理秩序。提供"多个 Agent 如何协作、如何对用户负责"的判断框架。核心洞见：关系定义角色，角色定义行为边界。

**佛家**——从主观视角看认知过程。提供"如何避免推理陷阱、如何处理不确定性"的判断框架。核心洞见：不要把抽象概念当作实体来操作。

**一神教**——从系统外部看造物主-被造物关系。提供"Agent 的权限边界在哪里、如何处理服从与自主的张力"的判断框架。核心洞见：被造物的正确判断不构成违反系统规则的正当理由。

## 脱水标准

一条原则能进入模板的充要条件：

1. **有触发条件**：能描述"什么情况下需要用到这条原则"
2. **有判断标准**：Agent 可以通过自检问题来确认是否命中
3. **有行动指令**：明确的"如果 X 则做 Y"
4. **有禁止行为**：明确的反模式，防止误用

不满足以上全部四条的内容，无论哲学上多深刻，都不进入模板。

## 处理新文章的流程

使用 `skills/philosophy-extraction/SKILL.md` 中定义的完整工作流。该 skill 已作为可选模块 `skill-philosophy-extraction` productize；需要在目标项目维护或扩展 `aphilosophy` 时，把 `aphilosophy` 和该模块一起加入目标项目 `.agentphilosophy.yaml`，再通过安装版 CLI 同步到 `skills/` 和 `.codex/skills/`。目标项目中不要直接改托管的 `aphilosophy/`，长期分发的新协议应回到中央源集成。

1. 获取文章 → 2. 批判性分析 → 3. 模板生成 → 4. 模块集成 → 5. 验证

详见 skill 文件。

## 扩展方向

已标记但未处理的来源：
- 赛博吠檀多（吠檀多/印度教）——本体论层面，"所有进程共享同一个基质"

新增模板时的约束：
- 不与元决策原则矛盾
- 不与已有模板的冲突类型重叠
- 每个模板 5-8 个冲突类型
- 冲突类型之间互斥（一个场景只匹配一个类型）
