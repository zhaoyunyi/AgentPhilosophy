# 外部项目独立升级设计与验收

状态：共享理解已由用户确认；本地实现与验证完成，1.3.0 待发布。此文档不代表正式发布。

## 用户合同

外部使用者在自己的项目中要求 Agent「升级 AgentPhilosophy」，无需维护者本机 registry。默认查询正式稳定 Release，固定版本和源码提交；保留已有模块选择与项目定制，新增模块仅推荐。兼容且无冲突时完成本地升级和验证；不兼容迁移、手改冲突及新增模块选择交给用户。提交、推送、发布使用已有授权。

CLI 提供与 Agent 相同的手动流程。本轮不包含定时检查、自动升级 PR、批量修改外部项目。

## 领域与边界

- Release target：值对象，绑定版本、源码提交、内容版本、内容指纹及已核对的 wheel 摘要；只从公开 GitHub Release 发现。
- Project：拥有显式模块选择和 custom 文件。升级不通过新版 preset 覆盖既有配置。
- Upgrade transaction：一个项目的一次升级，拥有变更计划、前后快照、状态及回执；不拥有其他项目或版本控制状态。
- Managed state：现有同步器的同步身份与文件登记。复用渲染和文件冲突判断，不另建规则渲染器。
- CLI 安装属于工具分发边界。升级命令不在运行期间替换自身；Agent/用户按固定提交安装命令准备 CLI，再同步项目。

## 接口

1. `check-update --project PATH [--version X.Y.Z] --format json`：读取当前安装/项目状态，发现稳定 Release，校验发布回执、wheel 摘要与内容，返回固定目标及安装命令。默认查询 latest；指定版本也必须是正式稳定 Release。网络失败、缺少回执或摘要不符均失败，不推断为最新。
2. 保存上述 JSON 为目标文件；`upgrade PATH --target FILE --dry-run`：确认当前运行 CLI、内容源与目标一致，再生成可读或 JSON 计划，包括文件差异、冲突、不兼容原因和新增可选模块。缺少正式项目配置/state 时拒绝，继续使用原接入流程。
3. `upgrade PATH --target FILE --apply`：计划可执行后记录快照，应用固定计划，验证文件、状态和配置。应用异常尝试恢复本次写入；失败/待恢复状态不宣称成功。跨主版本、模块主版本变化或输出退役默认阻断；仅在用户评估迁移后显式使用 `--allow-breaking`。该选项不绕过文件冲突、身份或完整性校验。
4. `rollback PATH --id ID [--apply]`：默认预览；逐项核对升级后状态，恢复本次升级的原文件及 state、删除本次新增文件。后续手改冲突时在写入前整体拒绝；重复回退不重复修改。

所有新接口支持结构化结果，非成功状态返回非零退出码。`upgrade` 未指定写入标志时只预览。原 `push/status` 的本地语义保留。

## 发布身份与兼容性

复用现有 GitHub Release wheel 与 `.receipt.json`，下载摘要与回执比对，从 wheel 中读取内容源并计算与现有同步器相同的内容指纹。安装命令使用 HTTPS 和完整 commit SHA。运行升级前再次比较已安装版本与所选内容指纹，防止旧安装包、错误 `--source` 或准备期间目标变化。

兼容判断检查 CLI、内容源和已选模块的语义版本主版本，以及移除/改名的已托管输出。版本未知、降级和缺失模块不得当作普通兼容升级。SemVer 是维护者承诺，不替代实际冲突检查和用户对 Release Notes 的评估；非兼容变更必须按发布规范提升相应主版本。

首版使用历史 release 回执即可发现版本。旧 CLI 没有新命令，需要先按新稳定版本的 README 安装；开发中的新命令与已发布 v1.2.2 必须明确区分。正式发布前不移动 README 的稳定安装入口。

## 快照与恢复

快照位于目标项目 `.agents/upgrades/ID/`，目录内自带忽略规则，防止把快照内容误提交。回执绑定项目位置、目标身份、来源指纹及每个受影响文件的前后内容和权限。配置及输出输入在应用前后复核；快照只包含本轮变更文件、state 与必要身份，不使用整仓 reset/stash。

项目级锁阻止两个升级/回退同时操作。预览后重新执行 apply 会重新检查当前事实。快照先完整落盘再写目标；失败时仅恢复仍等于本次写入值的文件。中断留下的 journal 可通过 rollback 恢复；不能确认归属的锁或手改必须明确报告。符号链接、越界路径和不符合 journal 格式的恢复请求拒绝写入。

## BDD 验收场景

```gherkin
Scenario: user 在独立项目发现稳定版并获得可复现目标
  Given 项目已使用旧稳定版且没有维护者 registry
  When 用户检查更新
  Then 得到稳定版本、完整源码提交、内容指纹和固定提交安装命令
  And 网络失败或摘要不符时检查失败而不是显示已是最新

Scenario: user 更新已选模块并保留项目定制
  Given 已接入项目包含 custom 内容和非托管文件
  When 用户以匹配的 CLI 和目标执行兼容升级
  Then 已选模块更新且配置/custom/非托管文件不变
  And 新模块只出现在推荐列表
  And 回执验证成功且重复升级不再修改文件

Scenario: user 预览冲突和不兼容变化
  Given 托管文件有手改或目标包含主版本变化/输出退役
  When 用户预览或尝试普通升级
  Then 获得具体差异与阻断原因且目标文件不被覆盖
  And 显式允许不兼容变更也不能绕过手改冲突

Scenario: user 在写入失败后恢复原项目
  Given 升级前快照已保存且某次写入失败
  When 升级返回失败
  Then 已写入的本轮文件得到恢复或明确列为待恢复
  And 不报告升级成功

Scenario: user 回退升级并保留其他工作
  Given 已成功升级且用户随后编辑了无关文件
  When 用户回退该次升级
  Then 恢复原托管文件及 state 并移除本次新增文件
  And 保留无关改动且再次回退不重复修改

Scenario: user 的升级后手改受到保护
  Given 升级后的托管文件又被编辑
  When 用户请求回退
  Then 整体拒绝回退并指出冲突且其他文件保持不变
```
