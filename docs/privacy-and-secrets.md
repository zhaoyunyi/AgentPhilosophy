# 公开仓库的个人信息与密钥防护

## 提交身份

维护者使用 GitHub 账户对应的 noreply 邮箱，避免把个人邮箱写入 author、committer 或 tagger 元数据。Git 与 jj 的仓库级身份需要分别配置；修改配置只影响后续提交，不能自动消除既有历史中的邮箱。

本仓历史的个人邮箱已按维护者授权替换。原历史仅保存在仓库外受限备份，不得重新推送。提交 SHA 和标签目标变化后，需要重新获取对应版本的发布目标与回执，详情见 [历史清理说明](history-cleanup.md)。本仓身份配置不修改维护者其他仓库的全局设置。

## 本地凭据与构建包

`.env`、`.env.*`、常见私钥和服务账号凭据文件默认忽略；`.env.example`、`.env.sample` 和 `.env.template` 保持可提交，但只能包含占位值。Git 忽略规则不会取消已经跟踪的文件，也不能防止强制添加，因此不能代替扫描。

含旧身份信息的本地构建包及旧回执已隔离到仓库外私有目录。`dist/` 用于本轮构建，不把历史包当作当前发布输入。正式制品必须经固定源码、版本和 SHA-256 回执校验后发布。

## 密钥扫描

Linux/macOS 安装 Gitleaks **8.30.1** 后执行：

```bash
bash scripts/check-secrets.sh .
python3 scripts/test-secret-scan.py
```

`check-secrets.sh` 扫描公开分支、标签和当前 HEAD 的完整 Git 历史，包含从最新树删除但仍在历史中的凭据。它不扫描未提交文件；提交前应检查实际 diff。配置固定使用本仓 `.gitleaks.toml` 的默认规则，不接受行内 `gitleaks:allow` 或调用目录中的忽略名单，日志始终遮盖值。

检测到疑似凭据、扫描器缺失、版本不符或执行错误时均返回非零退出码，不当作已通过。自测使用临时仓库和离线合成格式样本，不连接任何凭据服务，并验证干净历史、泄露阻断、历史残留及日志脱敏。

GitHub CI 的 `secret-scan` 作业会下载固定版本的扫描器、核对硬编码 SHA-256、执行自测并扫描历史。该作业与测试/构建作业一起判断 CI 是否成功。规则扫描不能保证发现所有未知格式秘密；Gitleaks 也不负责判断个人邮箱或项目名称是否应公开。

## 发现泄露后的处理

先定位文件、提交和暴露范围，不在报告中复制原始凭据值；真实凭据应先撤销或轮换。需要清除历史时，在备份与明确授权下改写相关分支和标签，并核对发布附件与回执。

GitHub 托管的旧 PR 引用、缓存，以及其他人的 clone/fork 需要分别处理；不能把公开主线扫描通过等同于旧对象已在所有位置删除。平台请求材料只通过私有支持渠道提供。
