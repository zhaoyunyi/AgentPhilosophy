# AgentPhilosophy 0.12.0

## 变更摘要

- 在测试策略中增加“编写测试注意事项”：通过公开接口验证业务结果、状态和副作用；业务合同不变的重构应继续通过原有测试，避免用内部方法调用次数等实现细节替代业务断言。
- 明确先根据需求编写 BDD 验收场景，再实现代码；测试描述统一以 `user` 开头，采用 Given / When / Then，覆盖成功路径和关键失败路径，AI 生成测试同样遵守。
- 补充“重复下单不会重复扣款”和“支付被拒绝后不会被扣款”示例，并同步 BDD 规范、AGENTS 导航及文档索引。
- 收录 v0.11.0 之后已合入主线的构建流水线调优能力：测试隔离、I/O 与缓存、Runner 预装工具、完整案例，以及用于核对测试清单和结果的只读比较器。

## 兼容性与迁移

- CLI 参数、公开接口和配置格式保持兼容；版本号在项目清单、运行时、锁文件、内容源与发布制品中一致。
- 依赖项目先更新 CLI，再执行 `validate`、目标项目 `validate` 和 `push --dry-run`，审阅测试规范与 AGENTS 的变化后 `push --apply`，最后检查 `status --project`。
- 本次只更新中央规范和本仓托管结果，不批量修改依赖项目或历史测试。新增或修改测试时遵循行为断言与 BDD 场景先行规则。
- 上游检查发现 Ponytail 有新的跟踪内容（最新正式版 v4.10.0）；其采用审阅不属于本次测试规范任务，继续保留已锁定快照。Matt skills 引用移动，但跟踪路径内容未变，不机械升级；其余锁定上游检查无变化。
- README 稳定安装入口在 GitHub Release 创建成功后单独更新；不可变发布快照中的 README 保留构建时的上一稳定 tag，制品元数据和运行时版本为 0.12.0。

## 回滚入口

上一正式版本为 `v0.11.0`。需要回滚时安装该 tag；目标项目应恢复其配置及匹配的托管文件、状态快照，先执行 dry-run，不能手工修改 state hash 绕过冲突保护。

## 发布回执

发布制品从固定源码提交构建，回执 `agentphilosophy-0.12.0.receipt.json` 绑定源码 SHA、CLI/content 版本和 wheel/sdist 的 SHA-256。正式发布以 [GitHub Release](https://github.com/zhaoyunyi/AgentPhilosophy/releases/tag/v0.12.0)、远端 tag 指向及下载后的摘要复核为准；本地测试和构建通过不代表已发布。
