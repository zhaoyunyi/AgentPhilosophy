# AgentPhilosophy 1.2.1

状态：发布候选。完成固定提交制品、远端 CI、tag / Release 与下载回读后，才标记正式发布。

## 变更摘要

- 正式分发 Loop-Check `1.0.1`：为每个仓库生成自己的每日/事件检查清单，在已有授权内完成检查、修复、复查与 PR。覆盖组件复用、文档代码一致性、迁移残留，并按项目事实选择测试、生成物、版本、证据和工作区检查。
- 统一退役规则：删除代码、文档、专属测试及失效引用，不保留占位；统一退役文档只记录对象/原路径和完整删除 Git 提交 SHA，处理提交自引用及 squash/rebase 后的追溯。
- 修正 JSON 配置向导推荐目录为实际默认的 `skills/` 与 `.agents/skills/`，明确单路或三路输出需要自定义模块；保留选项 ID 和旧 `.codex/skills` 兼容行为。
- 巡检计划路径遵循项目 `paths.custom_dir`，默认 `.agents/custom/loop-check.md`；同步不会覆盖自有计划或在自定义目录之外另建默认计划。
- 本版包含未单独发布的 `1.2.0` 能力与后续修复；稳定版本由 `1.1.0` 升至 `1.2.1`。

## 兼容性与迁移

- CLI 参数、state schema、JSON 格式版本和选项 ID 保持兼容。四类默认 preset 为新项目分发技能、支持文件与 metadata。
- 已有项目的 `modules` 清单显式冻结。升级 CLI 后，需把 `skill-loop-check` 追加到原有 `.agentphilosophy.yaml` 的 `modules` 中，再执行中央/目标 validate、push --dry-run、push --apply 和 status；不要替换项目原有模块清单。
- `doc-templates` 与 `repo-management` 升级后采用统一退役记录规则，不补造历史删除条目。
- 每日/事件检查是执行策略；技能安装不自动注册定时任务、hook、跨仓写入或自动合并。已有用户授权直接沿用，生产操作和发布仍遵循其各自范围。
- 本次不批量修改依赖仓库。本机 registry 中的项目需另行选择模块并同步；生成文件、宿主发现和实际执行分别验收。
- 发布提交的 README 保留已发布稳定入口 `v1.1.0`；Release 回读完成后再单独更新为 `v1.2.1`，避免引用尚不存在的 tag。
