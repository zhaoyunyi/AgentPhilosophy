# AgentPhilosophy v0.9.0 发布说明

## 变更摘要

- 将 AgentPhilosophy CLI 与中央内容源提升为 `0.9.0` 候选版本。
- Matt Pocock 上游锁定从 `ed37663cc5fbef691ddfecd080dff42f7e7e350d` 更新到 `6654f6b60cd9d5be8b54c6fafe44346dabeb3b76`。该 revision 的插件元数据版本为 `1.2.3`，并包含 `v1.2.3` 之后已进入 `main` 的修正。
- `skill-mattpocock-engineering` 升级到 `1.4.0`，`skill-code-review` 升级到 `1.1.0`，`skill-improve-codebase-architecture` 升级到 `1.2.0`。
- 默认 Matt 能力集从 22 个扩展为上游 manifest 当前声明的 25 个活跃 skills。

## Matt 工程能力变化

- 新增 `wizard`：为确实只能由人完成的控制台、凭据、迁移和切换步骤生成交互式 Bash 向导。
- 新增 `to-questionnaire`：把用户缺少的外部知识整理成给特定知情人的 Markdown 问卷。
- 新增 `wait-what`：补足上下文并用简单语言重新说明上一条消息。
- 采用 `writing-for-agents` 作为面向 Skill、`AGENTS.md`、`CLAUDE.md` 和下游 Agent 文档的新主入口。
- 保留 `writing-great-skills` 作为禁止隐式调用的兼容入口；同时继续保留 `to-prd` 与 `to-issues`，避免旧项目入口突然失效。
- `diagnosing-bugs` 增加秘密和观测产物脱敏合同，HITL 脚本明确不采集登录、MFA 或密钥输入。
- `prototype` 的逻辑分支改为自包含 HTML、状态面板、自由操作与 guided walkthroughs；UI 分支优先在真实页面使用受保护的 variant 比较，并把 prototype branch 保留为一手证据。
- `improve-codebase-architecture` 先按近期变更热区做 YAGNI scope，避免优先整理休眠代码。
- `ask-matt` 增加阶段边界决策树，收窄 `/handoff` 为跨工具、目录、仓库或协作者的可携带交接。
- 主动 skill 不再自动调用 `setup-matt-pocock-skills` 或其他仅用户调用的 skill；缺少前置配置时停止并请用户明确启动。
- 活跃入口中的旧 `PRD` 术语统一为 `spec`；旧兼容入口仍保留其历史命名。

## 有意保留的本地适配

Matt 上游当前 `grilling` 使用 frontier 批量轮次。AgentPhilosophy 继续遵循项目的一问一答约定，每次只让用户拍板一个决策；`grill-me`、`grill-with-docs`、`grilling` 与 `triage` 保持同一口径。这是明确适配，不是未完成的上游同步。

## 兼容性与迁移

- 新项目使用当前默认 preset 时，会同时生成 25 个活跃 Matt skills、3 个兼容入口、支持文件和 repo/Codex 双目标元数据。
- 旧项目的 `.agentphilosophy.yaml` 仍是显式冻结的；只有已经包含 `skill-mattpocock-engineering`、`skill-code-review` 或 `skill-improve-codebase-architecture` 的项目才会在 `status` 中看到对应模块版本 stale。
- 同步前依次运行 `validate`、目标项目 `validate` 与 `push --dry-run`；确认新增入口和旧兼容入口后再执行 `push --apply`。
- `writing-great-skills` 不会被直接删除，旧命令仍可显式使用，但新文档和新任务应改用 `writing-for-agents`。
- `wizard` 只负责生成人工执行脚本，不读取、记录或代填真实凭据，也不替代用户对不可逆动作的确认。

## 其他 Skill 上游审计

本轮只实现 Matt 模块升级，以下项目未混入代码改动：

- `skill-code-review-graph`：已锁最新正式 `2.3.8`，继续保持不动。
