# AgentPhilosophy v1.4.0 发布说明

状态：2026-11-16 已正式发布。固定提交 CI、远端 tag / Release、制品下载回读与真实正式版本间升级/回退验收均通过。

## 变更摘要

- 完善软件版本治理：明确主版本、次版本、修订版本的影响边界，同次发布取最高影响级别，高位递增后低位归零，并按一次正式发布汇总变更。
- 中央模板附带 `1.4.7 → 1.4.8 / 1.5.0 / 2.0.0` 示例，通过同步生成本仓及接入项目的 `AGENTS.md`；发布流程和文档索引提供统一入口。
- 本仓按相同规则发版：相对上一正式版 `v1.3.0`，本次增加兼容的发布治理能力，因此 CLI 与内容源统一提升至 `1.4.0`；包含的修复不重复累加版本。
- 纳入主线已完成的来源元数据隐私修正、凭据忽略和固定版本 Gitleaks 历史扫描，保留已审阅的 Portless 许可证内容。
- 修复更新发现测试对固定目标版本的假设：用当前版本的下一修订版构造离线测试目标，后续升版仍验证“发现更新”行为。

## 模块版本变化

- `release-conventions`：`1.1.0` -> `1.2.0`，发布说明目录、SemVer 版本口径和发布回执规则。

## 兼容性与迁移

- 原 CLI 命令、项目配置与 state schema 1 保留，无模块移除、输出改名或必需的手动数据迁移。
- state 的来源身份不再携带维护者本机绝对路径，使用便携标识；已有 state 可由正常同步或升级流程更新。
- 默认 preset 已包含 `release-conventions`。旧项目保留原有模块选择；未选择该模块的项目不会因安装新 CLI 而自动追加模块。
- 本仓 `AGENTS.md`、CLI 清单、运行时、锁文件、内容源清单和同步状态已采用本次规则及相应版本。正式 tag 内 README 保留上一已发布稳定安装入口，主分支通过发布后的独立提交更新为 `v1.4.0`。

## 依赖项目影响

- 已选择 `release-conventions` 的项目会收到版本规则更新，模块版本由 `1.1.0` 提升到 `1.2.0`。
- 使用 `check-update` 固定官方发布身份，再按[升级指南](../docs/cli/upgrade.md)预览、应用并保留回退 ID；本次发布不批量修改真实依赖项目。

## 外部技能上游

2026-11-16 完整检查发现：Matt 工程技能跟踪内容有变化（最新正式版本 `v1.3.2`），code-review-graph `v2.4.0`、Ponytail `v5.3.3`、Portless `v0.17.0`、Superpowers `v7.0.2` 可用，reverse-skill `v1.0.1` 仍为 current。本次聚焦版本治理，未采用尚未审阅的上游更新；已有依赖版本及上游 revision 保持不变。检查退出码 2 表示发现更新，不是检查失败。

## 回滚入口

- 项目内容使用 `rollback PROJECT --id ID --dry-run` 预览，再通过 `--apply` 恢复此次升级前的文件与 state；后续手改应触发冲突保护。
- CLI 本身可重新安装上一正式版 `v1.3.0`；回退项目内容不会自动降低本机 CLI 版本。
