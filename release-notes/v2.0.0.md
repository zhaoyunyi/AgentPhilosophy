## 兼容性与迁移

- 新项目使用当前默认 preset 时会获得本版本的默认模块集合。
- 旧项目的 `.agentphilosophy.yaml` 模块列表是显式冻结的；升级 CLI 不会自动追加新模块，先按发布摘要审查后再修改配置。
- 本版本包含模块版本变化；依赖项目同步前先运行 `status` 与 `push --dry-run` 审查影响。
- code-review-graph 2.4.0 会把本地图谱 schema 13 迁移到 15。升级前备份 `.code-review-graph/graph.db`，升级后运行一次全量 `code-review-graph build --repo .`；回退到 2.3.9 需要删除图谱并用旧版重建，VS Code 扩展也要支持 schema 15。
- Portless 0.18.1 对命令 flags、`clean` 确认、state 目录权限、并发 Turbo manifest 和 alias 删除做了行为收紧；项目脚本按新版本逐项验收，自动化清理使用 `--yes`。
- Ponytail 5.3.3 改为当前会话持续生效，新增 `off` 模式、最小完整变更和风险摘要；选择该模块的项目应重新阅读调用合同。
- Superpowers 7.0.2 只更新显式可选说明和插件版本，不自动安装插件或创建全局 discovery 入口。

## 依赖项目影响

- `agentphilosophy_version` 会写入依赖项目的同步状态。
- `source_content_version` 用于提示依赖项目是否需要同步新一轮中央内容。
- 默认内容源有文件变化，依赖项目同步前先运行 `push --dry-run` 审查托管输出计划。
- 依赖项目可能看到 `module version stale`，优先审查 `skill-code-review-graph`、`skill-code-review`、`skill-improve-codebase-architecture`、`skill-mattpocock-engineering`、`skill-ponytail`、`skill-portless-local-dev` 对应输出。
- 发版后运行 `uv run sync.py status` 查看 registry 中依赖项目是否 stale。

## 回滚入口

- CLI 或中央内容需要回退时，恢复到 `v1.5.0`，并保持 CLI、内容源与目标项目 state 的版本关系可解释。
- 回退后先运行 `validate`、目标项目 `status` 和 `push --dry-run`；不要直接用旧内容源覆盖已经由新版本写入且被人工修改的托管文件。
