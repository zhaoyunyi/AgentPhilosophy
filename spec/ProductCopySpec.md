# 产品文案与用户可见信息规范

先确定文字的受众和用途，再选择披露范围。相同对象可以在终端用户界面、开发者集成说明和内部诊断中采用不同粒度。

## 终端用户界面

- 用户可见文案不得解释内部实现细节；页面、toast、按钮、空状态和普通客户错误只表达用户理解的对象、状态、影响和下一步。
- 普通租户门户不得用文案区分产品 key 与上游或供应商 API key；这类内部边界不帮助用户完成当前操作。
- provider binding、runtime provider、adapter、allowlist、resource policy、raw ref 等内部对象进入普通用户界面前，先映射成产品状态。
- 不展示凭据值、secret hash、内部异常栈或上游原始错误体；诊断关联使用安全的请求编号。

例如，门户不使用“组织访问密钥用于服务端集成；它不是上游 API key。”，改为“创建和轮换组织访问密钥；新密钥只显示一次。”

英文同样避免在普通门户使用“Organization access keys are not upstream API keys.”，可用“Create and rotate organization access keys. New keys are shown once.”

## 开发者与客户集成文档

- SDK README、CLI 帮助、公开 API 文档和开发者工具可以准确说明用户必须配置的公开接口、依赖名称、供应商选择、认证方式及参数；不因词语出现在内部术语表中就删除必要事实。
- 当产品提供用户自选供应商、BYOK 或多种认证方式时，明确每种凭据的用途、来源和传递位置，帮助集成者正确配置。
- 只披露完成集成需要的公开合同，不泄露凭据值、内部拓扑、隐藏策略或敏感调试数据。
- 客户可见 API 错误提供稳定错误码、可操作原因和安全请求编号；公开的字段校验错误可指出调用者需要修改的参数。

## 内部诊断与项目扩展

- 内部 spec、测试、运维 runbook 和受权限保护的诊断页保留精确实现事实，并按数据敏感性脱敏。
- 具体产品的术语黑名单和渠道限制由该项目的配置、custom 规范或受众合同维护；不能把某产品的门户约束泛化为所有开发者工具的禁词表。
- 普通门户与内部诊断不能复用会泄露额外信息的错误文案组件。

## 验证

- 中英文按相同受众边界检查；不能只修改一侧。
- 用户流程变更或文案边界修复补充 unit、e2e 或 BDD 守卫，断言实际渲染结果与可操作行为。
- 同时验证终端用户不会看到无关内部细节，以及开发者仍能获得完成集成所需的准确接口信息。
