# 产品文案与用户可见信息规范

本规范约束所有用户可见文案、客户可读错误、公开文档、页面空状态、toast、按钮、表格列、表单说明、API 错误消息和端到端验收断言中会被客户或终端用户看到的文字。

## 核心原则

- 用户可见文案不得解释内部实现细节。文案只表达用户能理解的对象、状态、影响和下一步。
- 不得用文案区分产品 key 与上游或供应商 API key。产品可以有自己的访问密钥、组织密钥、网关密钥或集成密钥，但用户不需要知道它与哪个内部系统、供应商或上游 API key 的边界关系。
- 不把内部系统名、上游供应商名、provider、runtime、adapter、binding、allowlist、resource policy、capability、raw ref、trace、secret hash、token、credential、raw payload 等实现词和值暴露给普通用户。
- 可以在内部 OpenSpec、后端测试、运维 runbook、审计日志和开发者调试输出中保留精确实现事实；这些事实进入用户界面前必须经过产品化映射。
- 中英文文案同样适用本规范。不能只删除中文说明而保留英文解释，也不能把内部术语直接翻译成另一种语言展示。

## 禁止展示的文案形态

以下内容可以作为内部排查语境存在，但不得进入用户可见 UI、客户文档、客户可读 API 错误或公开帮助文案。

| 禁止形态 | 原因 | 推荐方向 |
| --- | --- | --- |
| `组织访问密钥用于服务端集成；它不是上游 API key。` | 用文案解释内部产品边界和上游 API key 差异 | `创建和轮换组织访问密钥；新密钥只显示一次。` |
| `Organization access keys are for server integrations. They are not upstream API keys.` | 英文同样暴露内部集成和上游命名 | `Create and rotate organization access keys. New keys are shown once.` |
| `需要配置 provider binding 后才能使用 runtime provider。` | 暴露运行时供应商和绑定实现 | `当前运行能力暂不可用，请联系管理员处理。` |
| `resource_policy_ref 不存在`、`adapter_unavailable`、`runtime_provider_unavailable` | 暴露内部字段名或实现错误码 | `配置未完成`、`服务暂不可用`、`请稍后重试或联系管理员` |
| 直接展示 token、secret hash、credential fingerprint、raw payload、trace id 以外的完整调试上下文 | 泄露敏感信息或内部拓扑 | 只展示安全的请求编号、时间、状态和可操作建议 |

## 用户界面文案标准

- 命名用户已经理解的产品对象，例如组织、项目、任务、访问密钥、运行记录、用量、成员、角色、账单、审计记录。
- 状态用产品语言表达，例如可用、不可用、配置未完成、处理中、已失败、已过期、已撤销、等待管理员处理。
- 操作文案说明用户下一步，例如创建、复制、轮换、撤销、重试、联系管理员、查看运行记录。
- 空状态说明当前没有什么、为什么可能为空、下一步做什么，不解释数据如何从内部服务聚合而来。
- 错误文案优先给稳定原因和恢复路径；只有内部工具、管理员诊断页或运维页面可以按权限展示更具体的实现线索。
- 公开文档使用产品概念和客户集成概念，不把供应商、上游 API key、内部 adapter、内部 role guard、DTO allowlist 作为面向客户的说明主体。

## API 与错误响应

- 客户可见 API 响应中的 `message`、`error`、`hint`、`description` 必须使用产品化语言。
- 可以提供稳定、产品域内的错误码，例如 `ACCESS_KEY_REVOKED`、`RUN_TEMPORARILY_UNAVAILABLE`、`CONFIGURATION_INCOMPLETE`。
- 不把上游 provider 原始错误体、内部异常类名、数据库字段、tenant guard、policy ref、capability key、adapter 名称传给客户。
- 如需排查定位，返回安全 request id 或 audit id，由后台日志关联内部细节。

## 内部与外部边界

- 内部 spec、单元测试、后端集成测试可以描述真实实现，例如某产品 key 不等同于某供应商 API key。
- 面向客户的页面、public docs、SDK README、门户、浏览器端错误、公开 API schema 和 e2e 用户行为断言不得复用这些内部解释。
- 管理员或运维页面如果确实需要展示内部对象，必须明确其受众是内部操作者，并避免与租户门户、客户门户、公开文档共用文案组件。

## 排查清单

完成用户可见文案变更前，至少检查：

- 搜索中英文内部词和供应商词，确认没有进入用户可见组件、页面、公开文档或客户可读错误。
- 针对新增或修复的文案补充 unit、e2e 或 BDD 守卫，断言渲染结果不包含禁止词，而不是只检查实现函数。
- 如果后端 DTO 必须包含内部字段，前端或公开 API 适配层必须先映射为产品字段；不要把 raw ref 透传到 UI。
- 浏览器或截图验收时查看真实页面状态，确认空状态、错误态、按钮、表格、帮助文字都符合本规范。
- 同一含义的中文、英文和双语文案要一起排查，避免只修一侧。

## 推荐替代表达

| 场景 | 推荐表达 |
| --- | --- |
| 访问密钥列表 | `创建和管理组织访问密钥。新密钥只显示一次，请妥善保存。` |
| 密钥已撤销 | `该访问密钥已撤销，不能继续用于请求。` |
| 运行能力暂不可用 | `运行能力暂不可用，请稍后重试或联系管理员。` |
| 配置未完成 | `当前配置未完成，请联系管理员完成设置。` |
| 请求排查 | `请求未完成。请稍后重试；如需排查，请提供请求编号。` |
| 用量为空 | `当前时间范围内暂无用量记录。` |
