# UI 原型

用于布局、交互、信息层级和视觉方向问题。

- 优先在目标功能现有页面和同一路由中创建约三种结构差异明显的 variant，通过 `?variant=<name>` 或等价参数切换；保留真实 header、sidebar、数据、权限和响应式上下文。
- 页面底部或固定区域提供显眼的方案切换器；覆盖核心状态、窄屏和关键交互，不把换颜色当成不同方案。
- 只有项目确实没有可承载问题的现有页面时，才创建隔离的 throwaway route；不要默认为 UI 生成脱离产品上下文的单文件 HTML。
- 复用项目已有设计 token 和组件以提高比较可信度。variant 和临时入口必须受开发环境或显式 feature flag 保护，不能进入生产导航或公开路由。
- 让用户实际查看或操作后再收敛，记录选择理由和淘汰方案。
- 选定后由正式实现重新满足响应式、无障碍和测试要求；主线移除 variant、切换器和临时入口，原型作为独立 branch 上的一手证据保留。
