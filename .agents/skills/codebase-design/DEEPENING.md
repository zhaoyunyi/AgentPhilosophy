# 深化模块

1. 按领域行为而不是文件类型圈定候选 cluster。
2. 列出进入 cluster 的调用、离开 cluster 的依赖和跨越的状态。
3. 将依赖分为稳定领域输入、可替换外部能力和内部实现细节。
4. 选择一个调用方已经需要的 seam，把可替换能力放成 adapter，把内部细节藏起。
5. 设计更小的 Interface，让调用方表达意图而不是编排步骤。
6. 用通过 Interface 的行为测试替换锁定内部协作者的测试。
7. 删除旧透传层，不在旧抽象外再叠一层新抽象。

完成标准：调用方更少知道内部步骤，变化集中，测试通过同一 Interface 验证真实行为。
