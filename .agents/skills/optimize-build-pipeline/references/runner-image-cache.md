## 1. 先核对真正运行的配置

同时记录源码模板和当前Runner Pod的imageID、资源与挂载。仓库已有工具Dockerfile不等于CI正在使用它；模板写1核也不等于现场已经从0.5核更新。

受控变更从现场配置做最小差异，保留此前WIP；镜像、CPU、卷与并发度不要无证据同时改。保存旧values/revision和回滚方法；重新读取配置确认只发生预期差异。

工具探测尊重当前PATH/HOME或显式配置的工具目录，不能绕过测试隔离去固定用户home找二进制。用实际`--version`证明工具可执行，并在新建Runner中确认setup步骤确实被跳过。

镜像选择器优先显式digest，其次保留现有专属镜像；仅真正不存在时采用约定默认。连接/RBAC/API错误不得吞掉后回退旧镜像，按容器名称查镜像而不是假定第0项。

## 2. 缓存收益与ownership

缓存分三种边界：包下载、编译输出、BuildKit层与cache mount。临时BuildKit的cache mount未必跨Pod持久，即使registry层缓存已经开启；必须从新Pod验证。

- 镜像先COPY锁文件/清单并建立依赖层，再COPY高频源码；版本/源码ARG或LABEL放到不需要重做昂贵RUN的后段。仍检查最终包版本与注入版本一致。
- 直接以最终UID/GID创建依赖，或在阶段交接时`COPY --chown`；避免后续`chown -R`对上一层整套依赖产生copy-up和大层重写。cache mount的uid/gid、应用HOME和显式cache目录必须一致。
- 精简context时逐项核对Dockerfile的COPY、构建插件及包内资源。不要为减小context排除实际需要的迁移、静态文件或许可证。
- 基础镜像使用现场验证的digest；第一次改变层结构会让昂贵系统依赖重新解包，必须计入新revision样本。不要把重新建缓存的一轮伪装成日常热命中。

预装工具后，原setup action的缓存功能可能同时消失。决定保留缓存时比较：恢复时间＋保存时间＋存储/维护成本，与重新下载/编译成本；第一次上传与精确key命中不保存分开测量。可用包管理器的CI prune机制减少不值得上传的数据，但先验证它不会删除唯一可用离线依赖。

cache key至少绑定系统/架构、toolchain和锁文件。宽前缀恢复只提供可重用下载，依赖仍须通过锁文件与摘要校验；不缓存credential config或整个home。

## 3. 预装工具与镜像权限

按工具实际下载耗时决定是否预装；固定版本和下载包摘要，镜像绑定源码revision、平台和工具版本，保留fallback或明确的不可用错误。

跨registry项目拉基础镜像失败时，先验证凭据的实际read/push范围与目标imagePullSecret，不因节点已有缓存就认定凭据有效。保持现有信任边界：

1. 优先由已授权的镜像owner发布到当前CI能读取的项目。
2. 如任务授权覆盖复制，可使用已有只读凭据，或从受控节点导出**已确认exact digest**的缓存镜像，再按现有目标项目权限导入。
3. 复制后核对manifest digest一致；平台选择可能从index变为单manifest时须明确记录两种身份，不能静默宣称同digest。
4. 临时凭据通过受控文件/stdin传递，限制文件权限，不出现在日志/argv/evidence；完成或失败后清理。无授权路线时报告阻碍，不默许扩机器人权限。

新Runner应独立拉取新digest并回读工具版本；节点缓存可以掩盖错误imagePullSecret，需要首次拉取证据。大型基础镜像复制/预装是一次性准备成本，单独记录，不混成日常workflow墙钟。

## 4. 并发完成与取消

每个组件独立context、log、metadata、digest和退出状态。监督器等待全部成功，再验证source、scan及receipt；`buildctl`失败须显式返回非零，不能使用旧metadata继续写成功回执。

必须验证这些路径：

- 双向barrier证明任务能重叠；全部成功后才继续。
- 任一组件失败、命令未能启动或结果缺失，停止成功路径并收回其他组件。
- SIGINT/SIGTERM首次到来记录退出意图；建立子进程时避免在登记之前异常跳出导致孤儿进程。
- 清理期间后续信号不能跳过清理；使用独立进程组或平台同等机制，按有界TERM→KILL等待并回收后代。
- 失败与取消仍保存独立日志，不让两个BuildKit的相同step编号混成不可解释记录。

进程组、信号与清理方式要适配平台；不把Unix supervisor无条件用于Windows。远端builder也要观察客户端取消后的任务是否结束。

对照不能只看job总时长。若并行job多97秒，其中独立工具下载多66秒，应分别报告；也不能把剩余差值直接认定为稳定并行代价。未证明收益时保持原默认。

## 5. 正式回读与资源清理

所有最终digest按目标平台独立pull/smoke，使用实际非root身份；至少核对版本、包导入、必需CLI/静态文件及退出码。业务调用不在授权范围内时，用不需要业务凭据的检查，明确它不证明生产业务闭环。

保存实际检查输出和imageID，不只写“smoke passed”。证据目录按文件生成manifest并重新校验；glob/csv输出采用LF，避免CRLF触发仓库差异检查。检查`.gitignore`是否吞掉被索引引用的`.log`，必要时改为脱敏文本回执。

记录并清理采样器、waiter、临时Pod、节点导出文件、凭据和临时values；停止只针对本任务精确PID/资源，不使用大范围kill/delete。核对产品引用、工作区与最终平台状态，交代未测量的冷/热/并发边界。
