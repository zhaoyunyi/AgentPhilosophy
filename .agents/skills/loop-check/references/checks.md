# 巡检候选

建立或调整本仓清单时读取；执行时只读取已启用项涉及的材料。下面是候选维度，不是每天必须全部运行的门禁，也不把某个历史项目的技术栈或权限要求套到其他项目。

| 候选 | 适用与触发 | 可观察的检查及修复依据 |
| --- | --- | --- |
| 组件与逻辑复用 | 新增组件、适配器、类型或重复规则；每日增量 | 检索现有公开接口和调用方，比较语义与领域边界。复用已有 owner；相似代码但不同合同不强行抽象或跨领域共享内部状态。 |
| 文档、代码与规格一致性 | 接口、配置、行为或目录变化；每日增量 | 对照 README/入口、OpenSpec、公开 API、示例、真实实现与测试；修复失效命令、旧字段、错误状态和无入口文档，维护对应索引。 |
| 迁移与退役残留 | 替换、重命名、迁移完成后；周期复核未完项 | 盘点旧入口、桥接、兼容层、旧依赖、测试/fixture、配置、脚本与文档引用；验证消费者迁移及替代行为后删除，按 SKILL 的唯一退役索引合同追溯。 |
| 测试有效性 | 行为变化、清理测试或 CI 异常 | 测试验证用户可观察结果；成功和关键失败路径仍覆盖。查无理由 skip/xfail、空断言和仅绑定内部细节的测试，避免测试与错误实现一起自证。 |
| 单一规则来源与跨仓合同 | 重复 owner、跨服务协议/领域变更 | 从权威合同对照生产者、消费者、版本和序列化字段，发现平行规则或直连其他领域内部状态；未得到外仓当前证据的部分标未验证。 |
| 配置与生成物漂移 | 改模块、模板、锁文件或同步工具后 | 对照源、镜像、配置、state/hash、真实运行入口；用生成器修复。skill 文件存在、宿主发现和实际执行分别验证。 |
| 版本与发布一致性 | 版本更新、发布前后 | 按独立版本轴核对清单、运行时元数据、锁文件、发布说明、tag/制品回执；未发布只报告候选。 |
| 验证与完成声明 | PR/CI/部署/业务状态变更 | 当前 revision 的检查终态、部署身份和业务验收分别取证；绿测、Ready、健康接口和已合并 PR 不替代业务结果。历史证据不自动刷新时间。 |
| 工作区与恢复价值 | 维护开始前；准备清理时 | 看 jj/Git、主线与远端、WIP、进程、工作区依赖、未合入补丁及唯一恢复价值。按年龄、目录名或“已合并”猜测可删都不充分。 |
| 缓存与构建成本 | 缓存/磁盘增长、CI 回归 | 归因缓存来源、大小、活跃工作区和重建成本；区分基础设施失败与代码失败。只清理明确授权且不活跃的对象，不为降低耗时取消测试或扩大重试。 |
| 运行恢复与幂等 | 仓库有异步 job、外部写入或重试逻辑 | 检查 unknown/reconciling 是否仍以原身份对账，是否重放已发生的副作用或遗漏取消/清理；纯静态检查不能冒充真实外部验收。 |
| 敏感信息与文案边界 | 日志/报告、配置、用户界面变更 | 只报告敏感信息位置，不输出值；区分终端用户、集成开发者与内部诊断，检查实际渲染，避免内部拓扑和凭据外显。 |
| 巡检自身有效性 | 每轮结束；计划调整 | 同根因是否重复创建 PR，任务是否重叠，历史未解决项是否被丢弃，失败是否被写成通过，是否无进展循环；没有可行动变化不刷通知。 |

优先把仓库最近反复出现且能低成本复核的问题加入每日项；高成本全量测试、跨仓取证、发布或运行时检查按事件/周期安排。检查方法必须指向当前仓库的真实入口，记忆中的旧命令、SHA、路径和线上状态不能直接作为当前结果。
